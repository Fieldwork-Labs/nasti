## Decisions

- DB fixes go in a **new** migration (`20261009000004_review_fixes.sql`) rather than editing the squashed ones, so the user can apply without `db reset`. (Previous session edited `20260911000001` in place under a "not in prod, scorched earth" policy; both are acceptable.)
- Test-edit finding: immutability (trigger + locked UI) instead of a reconciling correction RPC — simpler, reviewer offered it as an option.
- Collection atomicity: stable client-generated id (reviewer's "retries retain the same ID" option) rather than a transactional RPC. Origin-batch trigger is `AFTER INSERT`, so an upsert retry hitting ON CONFLICT doesn't create a second batch.
- Did **not** change `stringToNumber`'s null handling globally: mobile `collections/$collectionId/edit.tsx` uses it for latitude/longitude with null defaults; making null stay null would turn today's silent `POINT(0 0)` into `POINT(null null)`.
- Legacy edge-function path removed outright because nothing on `main` or this branch sends `assignment_id` (the testing feature is unreleased).
- Trigger function `fn_guard_quality_test_consumed_weight` revoked from `PUBLIC, anon` only (matches repo pattern for trigger functions).
