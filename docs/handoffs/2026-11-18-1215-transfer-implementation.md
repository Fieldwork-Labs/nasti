## Confirmed behaviour

- **Opt-out.** An Admin turning off incoming transfers immediately blocks new sends, closes pending incoming transfer requests and releases their bags. Accepted incoming links lie dormant and reactivate on opt-in. The settings UI explains both effects. A split portion released this way stays a separate bag.
- **Storage provenance.** Capture dates and durations at completion. For a split or merge ancestor, end the period when the transferred seed left that bag. Exclude later periods and carry forward validated snapshots from earlier receipts. Locations, containers and private notes stay out of the record.
- **Test provenance.** Capture results at completion. Return one latest result per test type or quality subtype across valid captured hops, with its date and performing organisation. Later edits or deletions leave the snapshot intact. Omit `plsCount` and `psuCount`, which estimate counts for the source batch. Project the permitted statistics and repeat fields explicitly.
- **Cleaning.** Let recipients clean collectionless received bags using their own species record and the source collection code. The cleaned batch keeps that source code for onward transfer and starts a fresh test history. The original received item pointer belongs to the original receipt.

The feature sends whole bags or weighed portions. A first send to an opted-in organisation reserves the bags until a recipient Admin approves the directional link. Later sends complete immediately while the recipient is opted in. The recipient gets its own batch and bag. The sender's moved weight is retired through the ledger. Testing providers use an **Owned** view alongside **Assigned**. [Plan decisions](../plans/2026-11-18-transfer.md#decisions-this-plan-builds-on)

## Implementation sequence

1. **Schema and access.** Write the enum migration first and use a second forward migration for dependent constraints, validators, tables, RPCs and grants. Keep the one-open-request index specific to `kind = 'transfer'` so existing duplicate testing requests can survive the migration. Scope legacy link writes and reads to testing as specified in §1.4. Protect the settings and provenance columns from direct client writes. Keep reservation and snapshot tables behind RPCs. [Schema](../plans/2026-11-18-transfer.md#1-schema-two-forward-migrations)
2. **Lifecycle and replay.** Lock the recipient organisation row, then the directional pair, then source bags and batches in stable order. The settings RPC must take the conflicting recipient lock and close pending requests and release their reservations atomically. Persist a client-generated request ID per sender org. A retry of the same confirmed payload returns the existing transfer and skips email. Reject reuse with changed input and claim the key before splitting. [Locking and state rules](../plans/2026-11-18-transfer.md#21-locking-and-state-rules-all-lifecycle-functions), [Send RPC](../plans/2026-11-18-transfer.md#23-fn_send_bags_for_transferp_recipient_org_id-uuid-p_bags-jsonb-p_notes-text-p_request_id-uuid), [Availability RPC](../plans/2026-11-18-transfer.md#29-set-incoming-transfer-availability)
3. **Inventory writers.** `fn_merge_batches` and `fn_mix_batches` consume inventory through `batch_merges` and can bypass bag-level triggers. Check every affected bag under lock before validating or consuming weight. Use the same active-inventory criteria on send and accept. Move direct web storage edits behind a bag-first RPC and close the direct authenticated update path. Keep storage completion internal, since the accepting Admin belongs to the recipient. Add the collectionless cleaning path and propagate `source_collection_code` during cleaning. [Merge and mix](../plans/2026-11-18-transfer.md#28-locking-reserved-bags), [Cleaning](../plans/2026-11-18-transfer.md#210-clean-received-bags), [Direct storage caller](../../apps/web/src/hooks/useBatchStorage.ts#L376)
4. **Provenance and UI.** Capture both snapshots in completion. Check caller ownership of the requested received batch, then verify each earlier hop against its completed mapping. Rank across the captured test candidates and return the winners. On the web, wire the opt-out toggle to its RPC, retain the request ID for retries, and allow batch detail to load when there are no local tests. [Provenance](../plans/2026-11-18-transfer.md#27-read-functions-for-the-recipient), [Web UI](../plans/2026-11-18-transfer.md#4-web-ui-appsweb)
